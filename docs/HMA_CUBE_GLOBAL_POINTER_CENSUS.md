# Whole-ROM GBA pointer-candidate census (29 October 2026)

`auditHmaCubeGlobalPointerCandidates` performs an optional **read-only**, all-byte-window scan (aligned and unaligned four-byte candidates) of a locally supplied ROM (4 bytes to 64 MiB). It examines 1–160 bounded decoded record ranges (up to 4,096 total range bytes) from a validated five-kind CUBE transaction. It reports aggregate pointer-shaped word counts, never ROM bytes, source offsets, local paths, or digests.

The scan distinguishes canonical `0x08000000 + targetOffset` candidates from `0x0A000000` / `0x0C000000` alternate-window candidates. On expanded ROMs, a word can match both interpretations; ambiguous hits are counted explicitly. Repeated record ranges are deduplicated for target bytes. Scanning a ROM is not the same as parsing its pointer ownership graph: arbitrary data may look like a pointer, compressed or computed references are not inspected, and an array may be referenced through a pointer to its beginning rather than to an edited record. Zero candidates cannot establish safety.

Aligned and unaligned hits are reported in separate counters; legacy aligned counters retain their existing meaning. The rolling scan reads each source byte once, and counts all possible four-byte windows. A hit inside a decoded record is not proof that the record is owned by the referring structure. The expanded-ROM mirror ambiguity and data false positives remain unresolved. Even a complete raw byte-window census cannot prove semantic ownership or authorize writes.\n\nThe local `npm run smoke:cube-combined -- ...` command now performs this census after independently re-decoding the proposed five-kind transaction and checking the explicitly declared map-bank ownership subset. Its JSON `globalPointerCensus` contains only counts and explicit non-authorization flags. Mobile previews do **not** perform a whole-ROM scan on the UI thread. The local-only adapter `auditHmaCubeGlobalEditPointerCandidates` derives bounded target spans from the five existing source-validated preflights, without changing the browser ownership auditor or its generated offline HTML.

**Safety boundary:** This is additional alias *discovery*, not independent CUBE ROM/TOML authentication, exhaustive semantic pointer ownership, edited-ROM save/reopen, emulator acceptance, Android hardware acceptance, or strict feature parity. It does not create patched ROMs or authorize semantic writes. All existing safety gates remain enforced. Synthetic regressions cover canonical/mirrored candidates, expanded-address ambiguity, unaligned hits, malformed input, source preservation and local CLI aggregate-only output.
