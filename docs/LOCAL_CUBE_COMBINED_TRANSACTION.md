# Local five-kind CUBE transaction acceptance rehearsal

The local-only command `npm run smoke:cube-combined -- --rom /local/user.gba --metadata /local/cube.toml --expected-sha256 <64-hex> --bank-index 0 --map-index 0 --map-count 1 --plan /local/edits.json --banks 0:1` tests a proposed transaction **without saving any edited ROM**. The example bank count is illustrative, not an assertion about any particular CUBE ROM.

The plan is a UTF-8 JSON object with up to five arrays: `cells`, `warps`, `events`, `connections`, `scripts`, each containing up to 32 existing editor-format proposals. A `viewport` object may supply `x`, `y`, `viewportWidth` and `viewportHeight` for cell edits. All five arrays are optional individually, but at least one proposal is required. See `tests/hma-cube-combined-transaction.test.mjs` for exact five-kind proposal examples and `tests/local-cube-combined-transaction.test.mjs` for a fully synthetic local acceptance fixture.

The command checks the exact caller-declared ROM SHA-256, requires unambiguous custom map-bank metadata, rejects symlinked or changing local input files, validates each proposed change against original bytes, applies all five kinds to an isolated in-memory snapshot, re-decodes the affected records, verifies rollback and original byte preservation, and independently rechecks edited-byte ownership intersections across the explicitly counted banks. The ROM is reopened and compared again after the rehearsal. It returns only aggregate counts, booleans and fixed warnings. No local paths, SHA digests, ROM bytes or patch files appear in the successful report. The CLI failure message is deliberately generic.

**Limits:** Bank declarations are caller supplied and capped at 8 banks / 256 maps; they are not a complete ROM pointer graph. Even zero detected conflicts cannot prove exclusive ownership. The SHA-256 is user supplied, not independently authenticated. There is no edited-ROM export, global alias proof, script execution, emulator acceptance, Android hardware verification or strict six-evidence feature parity. The utility never authorizes writes. `scripts/local-rom-atomic-saveas.mjs` remains a separate, byte-identical unmodified-ROM Save As operation.

This workflow is intended to gather reproducible acceptance evidence locally without committing or uploading copyrighted ROM files or private data. Review its aggregate results alongside actual CUBE/CUBHMA upstream behavior before any future write-capable feature is considered.
