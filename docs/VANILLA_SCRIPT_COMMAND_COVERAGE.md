# Conservative vanilla script command coverage expansion

Source: pinned [CUBHMA scriptReference.txt](https://github.com/kcradi/CUBHMA/blob/3044393183e01af2ae1e907fb37e4a75eda6a8dc/src/HexManiac.Core/Models/Code/scriptReference.txt). The mobile prefix decoder now recognizes additional **fixed-width** vanilla RSE/FRLG opcodes for music, warps, items, NPC movement, simple trainer flags, and message/lock controls. It preserves each operand's exact byte offset and raw value, and classifies conventional ROM pointers without following them.

Warps that transfer control (39–3D) terminate the sequential preview. Script bytes after a warp are **not** automatically part of that execution path. The grammar is intentionally incomplete: 2C has family-dependent width, 5C trainerbattle subtypes 00–08 use explicitly pinned widths; subtype 09+ is unsupported, and unknown commands stop inspection rather than guessing lengths. Commands that block temporarily are not interpreted as execution barriers unless the existing conservative terminal policy requires it.

This feature does **not** authenticate CUBE expansions, validate executable script ownership, follow control flow, execute scripts, authorize editing, or count as independent parity evidence. Synthetic tests exercise offsets, pointer values, family handling, budgets, terminal warps, and rejection of ambiguous opcodes. Genuine ROM/emulator/Android acceptance remains outstanding.
